# 工作排程表

管理工令排程的 Windows 小程式：記錄每個工令的材料入場、配電、出料、交期，預計日期和實際完成日期分開填，逾期或快到期的會用顏色標出來。

## 功能

### 每筆工令記錄
- **工令、機種、數量**（必填）、**客戶**。
- **CE / TS**：兩個勾選框，可以都勾、勾一個或都不勾。
- **日期**：材料入場、配電、出料、交期四個時間點，各自分成「**預計**」和「**實際完成**」兩格。
  - 按欄位右邊的日曆圖示（或 Alt+↓、F4）從月曆挑日期，只有日期、沒有時間；月曆下方可以一鍵填「今天」或「清除」。
  - 也可以直接打 `2026/10/06`、`2026-10-6`、`20261006`，或只打 `10/6`（自動補今年），全形數字也可以；離開欄位時會整理成 `2026/10/06`。
  - 還沒完成就留空白。
  - 預計日期前後顛倒（例如材料比交期晚到）時會提醒確認。
- **盤內配電、盤外配電**：負責的人。
- **耗材提供**：耗材由誰提供（例如公司、客戶、廠商）。
- **備註**：有寫備註的工令，清單上會出現小圖示，滑鼠移上去就看得到。
- **下拉選單**：機種、客戶、盤內 / 盤外配電、耗材提供可以直接打字，也可以從下拉選單挑之前輸入過的（最近用過的排前面）。
  - 打字時只列出包含輸入文字的項目；按右邊的 ▾ 或 ↓ 鍵列出全部。↑↓ 選擇、Enter 帶入、Esc 關閉。
  - 存檔、匯入 Excel 時會自動記住新的值；盤內、盤外配電共用同一份人員清單。
  - 打錯的可以按該項右邊的 ×（或選到後按 Shift+Delete）從清單移除，不影響已經存好的工令。

### 清單與狀態
- 每個日期格顯示「預」「實」兩行，顏色代表狀態：
  - 綠色：準時完成。
  - 橘色：3 天內到期，或已完成但比預計晚。
  - 紅色：已過預計日期還沒完成。
- 每筆工令的狀態：填了實際交貨日期就是**已完成**；材料入場、配電、出料、交期任一項逾期就是**逾期**；其他是**進行中**。
- 上方的卡片可以篩選「全部／進行中／逾期／7 天內交貨／已完成」，並顯示各有幾筆。
- 可以搜尋工令、機種、客戶、人員、耗材、備註，也可以切換排序（預計交期、預計材料入場、預計配電、預計出料、工令、客戶）。
- 同一個工令重複輸入時會先詢問。

### 四種檢視

標題列右邊可以切換，程式會記住上次看的是哪一種。點甘特圖的一列、時間軸或看板上的卡片，右邊表單就會打開那筆工令。

- **清單**：上面說明的表格。
- **甘特圖**：每筆工令一列。
  - 粗條是預計日期：淺色段是「材料入場 → 配電」，深色段是「配電 → 出料」，紫色段是「出料 → 交期」。
  - 下方綠色細條是實際完成的日期，虛線表示目前進行到哪裡（從最後一個實際完成日到今天）。
  - 菱形是預計日期、圓點是實際日期，顏色和清單一樣（紅色逾期、橘色快到期或延遲、綠色完成），紅色直線是今天。
  - 可以切換「日 / 週 / 月」縮放，按「今天」捲回今天。按住 Shift 滾滾輪可以左右捲動。
- **時間軸**：所有工令的材料入場、配電、出料、交貨依日期排成一條線。已完成的放在實際日期，還沒完成的放在預計日期。
  - 預設只看「近期」（前 2 週到未來 2 個月），逾期還沒完成的一律顯示；也可以切到「全部」，或隱藏已完成的項目。
- **資訊看板**：一眼看出目前狀況（看全部工令，不受篩選影響）。
  - 數字：未交貨工令、逾期、7 天內交貨、本月已交貨、準時交貨率、全部工令。
  - 清單：逾期未完成、接下來 7 天要做的事、最近交貨。
  - 圖表：未來 8 週每週要交貨幾筆、每位配電人員手上有幾筆、各客戶有幾筆。點人員或客戶會切到清單並搜尋。
    同一格寫好幾個人時（例如「阿明、小陳」）會分開計算。

甘特圖和時間軸使用和清單相同的篩選與搜尋，甘特圖也依清單的排序方式排列。

### 其他
- 匯出 / 匯入 Excel（工作表「排程表」，一列一個工令）。匯入時依第一列的標題找欄位，欄位順序可以調換；
  可以選擇「合併」（工令相同的以 Excel 為準更新）或「完全以 Excel 為準」。
- 支援淺色、深色、跟隨系統三種主題。
- 線上更新：開啟程式時會檢查 GitHub Releases，有新版會詢問是否更新。

## 安裝

1. 到 [Releases](https://github.com/asdZzz-coder/wsi_work/releases) 下載最新的 `WorkSchedule-ClickOnce.zip`。
2. 解壓縮整個 zip。
3. 執行 `安裝.cmd`。

安裝完成後，開始功能表和桌面都會有「工作排程表」的捷徑。

資料存在 `%AppData%\WorkSchedule\schedule.json`，是一般的 JSON 檔，可以直接備份。換電腦時用「匯出 Excel → 匯入 Excel」搬資料。

## 開發

需要 .NET 10 SDK。

```bash
dotnet build schedule.slnx
dotnet test schedule.Tests/schedule.Tests.csproj
dotnet run --project schedule
```

測試時可以設定環境變數 `WORKSCHEDULE_DATA_DIR` 改用別的資料夾，就不會動到正式資料。

## 發佈新版本

推送 `v*` 標籤後，GitHub Actions 會依序執行：

1. 跑自動測試。
2. 用 ClickOnce 打包。
3. 把 `WorkSchedule-ClickOnce.zip` 上傳到 GitHub Releases。

```bash
git tag v1.0.0
git push origin v1.0.0
```

### 智慧型應用程式控制

開著 Windows「智慧型應用程式控制」的電腦，會依檔案內容擋下某些沒有簽章的 `WorkSchedule.dll`，程式一開就關掉（v1.0.0 就發生過）。
所以 Release 版設成不論在哪裡建置都產生一模一樣的檔案，SDK 版本也用 `global.json` 固定。發佈前可以先在本機確認：

1. 用 Visual Studio 的 MSBuild 執行和 `release.yml` 相同的 Publish 指令。
2. 開啟 `clickonce\Application Files\WorkSchedule_x_x_x_x\WorkSchedule.exe`，確定沒有被擋下。
3. 再推送標籤。GitHub Actions 的記錄會印出 `WorkSchedule.dll` 的雜湊值，可以和本機的比對。
